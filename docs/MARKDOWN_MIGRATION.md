# 文件命名与 Markdown 图床替换

## 自定义文件名

进入“设置 → 文件命名 → 自定义命名”。输入框下分组展示变量的作用和格式，点击可将变量插入光标位置，或替换当前选中的文字。扩展名自动保留；无需再写 `.jpg` / `.png`。

| 变量 | 说明 |
| --- | --- |
| `{date}` | 上传时的设备本地日期，如 `2026-10-06` |
| `{Y}` / `{year}` | 四位年份；`{y}` 为两位年份 |
| `{m}` / `{month}` | 两位月份 |
| `{d}` / `{day}` | 两位日 |
| `{h}` / `{i}` / `{s}` | 小时、分钟、秒 |
| `{ms}` | 三位毫秒 |
| `{timestamp}` | Unix 毫秒时间戳 |
| `{filename}` | 原始文件名，不含扩展名 |
| `{md5}` | 原文件内容的 32 位 MD5；不是随机值 |
| `{md5-16}` | MD5 前 16 位 |
| `{sha256}` | 原文件内容的 SHA-256 |
| `{uuid}` | 不含连字符的 UUID |
| `{str-8}` / `{str-16}` | 随机字母数字串；可改为 1–128 位 |

示例：`{date}_{md5-16}`。未知变量、路径分隔符、过长随机串会报错；最终文件名限制为 240 个 UTF-8 字节。命名与普通上传共用实现；开启压缩时摘要仍取压缩前的原文件内容。

## 一键替换图床

上传页 → 一键替换图床：

1. 用系统文件选择器选择 UTF-8 编码的 `.md` / `.markdown` 文件。
2. 选择具体图床配置。任务固定使用此配置，不改变上传页默认或临时目标。
3. 选择“另存新文件”或“覆盖原文件”。默认另存，成功处理后由系统保存器选择位置。
4. 开始替换，查看进度和处理结果。

支持 Markdown 内联图片、显式/折叠/快捷引用式图片、HTML `<img src>`，包括列表和引用块内的图片。匹配图片外层链接与图片地址相同的情形会一并更新，普通文本链接不改动。引用式图片转换为内联图片，保留说明文字与标题；原有链接定义保留，避免影响普通引用链接。

只处理有效 HTTP/HTTPS 图片，协议相对地址 `//host/image` 按 HTTPS 处理。本地路径、data URI、代码块、行内代码、注释不上传。重复地址只下载、上传一次，成功后替换所有对应图片引用。复杂的非标准 Markdown 语法仍建议核对输出。

下载后沿用应用的命名、图片处理和相册记录流程。单图按流写入应用目录，最大 50 MB；请求总超时 45 秒，并有 20 秒接收超时与最多 5 次重定向。文件最大 10 MB，一次最多 1000 张不同的远程图片。原 UTF-8 BOM、CRLF/LF 和未替换的内容保留。

## 失败、停止与报告

- 下载/上传逐张处理。失败不影响后续图片，只替换成功的地址，失败链接保留原样。
- HTTP 404 / 410：图片已失效或被删除。
- HTTP 401 / 403：登录、鉴权或防盗链限制。
- HTTP 429、域名解析失败、超时、TLS 证书错误、网页冒充图片、空图片、体积超限均有明确提示。
- 点击“停止任务”会停止后续图片并中断当前下载；正在执行的上传会完成。不会自动写文件，可选择保存已完成部分。
- 保存器取消或写入失败后，处理结果保留在当前页面。可以改用另一输出方式再次保存，不会重新上传图片。
- 未保存的成功结果离开页面时会提示确认；已上传图片仍在相册。
- 页面逐条展示失败阶段、链接、原因和诊断编号。可导出完整处理报告，包含脱敏网络信息、上下文与堆栈；错误快照保留在本次结果中，不依赖全局日志的 300 条上限。

任务期间不应清除应用数据或强制结束进程。已经上传到图床的图片不会因停止任务自动删除。

## Android 文件读写与原文备份

不能把 FilePicker 的缓存路径当作原文件。因此此功能使用 Android Storage Access Framework：

- `ACTION_OPEN_DOCUMENT` 读取用户选择的文档 URI。
- `ACTION_CREATE_DOCUMENT` 另存结果或报告。
- 覆盖使用原文档 URI，通过 ContentResolver 写入，而非修改缓存副本。

覆盖前将原始字节备份到应用支持目录 `markdown-backups/<UUID>.md`，并由原生接口比较当前文件 MD5 与选择时的 MD5。文件已被其他程序修改时拒绝覆盖，用户可重新选择或另存。

写入后读回校验。若写入失败，尝试检查并恢复原文；无法确认恢复时明确显示恢复错误。SAF 的云盘等提供者无法统一保证原子替换，因此始终保留应用内的原文备份，并提供“导出原文备份”。备份包含原文内容，保存于应用私有目录。

图片成功后保存在应用文档目录 `markdown-images/<任务时间>/<序号>/`，用于相册本地预览；失败下载的中间文件会清理。输出位置由用户在系统文件界面决定。

## 开发与验收

- `filename_template.dart` / `filename_template_sheet.dart`：统一命名解析、输入校验、点击插入。
- `markdown_images.dart`：独立 isolate 解析与有位置的文本替换。
- `markdown_migration.dart`：流式下载、去重、停止、逐条失败隔离、报告。
- `markdown_documents.dart` / `MainActivity.kt`：文档选择、输出、备份、MD5 冲突检测与原文恢复。
- `markdown_migration_page.dart`：文件、目标、输出方式、进度与结果。

`test/markdown_features_test.dart` 覆盖哈希、插入选择、图片语法、跳过代码、列表与引用、重复地址、本地 HTTP 410/403/HTML、体积与超时、停止、BOM/CRLF、文档 URI / 校验和 / 备份与窄屏界面。数据层测试验证多图片始终上传到所选配置并写入该配置的相册。

本机可用 `tools/check-documents-native.ps1` 独立检查 Kotlin 文档接口，复用缓存的 Kotlin 2.1、Flutter Android 类库、Android SDK 36、Java 21；输出 `.class` 到 `artifacts/kotlin-documents-check/`，不调用 Gradle、不生成 APK。这不能替代真机验证。

真机需要验收：本地 Downloads 文档、云盘只读文档、覆盖/另存、保存器取消、处理中修改原文件、部分失效链接、断网、停止任务、BOM/中文/CRLF、备份导出与存储空间不足。当前仅做自动化和独立编译检查，未做新 APK 或真机测试。
