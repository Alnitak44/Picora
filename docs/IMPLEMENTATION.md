# 实现与验收说明

## 界面定位

定位为安卓 PicGo，主页直接呈现操作，不设置标语、生活化文案或装饰性顶部横幅。仓库页标题为“图床列表”，新增配置默认使用平台名称；用户已有的自定义名称不自动更改。设置页提供“浅色 / 自动 / 深色”，选择保存后即时生效，自动模式随系统亮度变化。

## 架构

`lib/hero/` 是新前端。`main.dart` 同步初始化路由并安装 Flutter、平台与异步异常捕获，随后运行 HeroApp。PicoraController 初始化上游服务；首次配置读取失败时显示可重试的启动错误，不隐藏故障。

- `hero_theme.dart`：蓝白/深色设计系统、统一反馈与卡片。
- `hero_app.dart`：四页导航、玻璃底栏、转场、系统分享接收。
- `upload_page.dart` / `album_page.dart` / `repositories_page.dart` / `settings_page.dart`：重写的主页面。
- `controller.dart`：独立配置选择、上传预处理、上游 API 调用、相册记录与辅助时间信息。
- `models.dart`：与上游完全对应的十二种图床字段。
- `config_exchange.dart`：Picora 备份、PicHoro 分组与 PicGo/PicList 参数转换；导入前验证必填字段和容量。
- `diagnostics.dart` / `diagnostics_page.dart`：结构化异常记录、查看、复制、分享导出。
- `lib/hero/plugins/` / `plugin_page.dart`：ZIP 插件包、独立元信息与 HTTP 程序、资源和离线教程、权限校验、旧版迁移、插件生命周期与 PicGo Server 桥接；示例源码在项目根目录 `plugins/`。
- `compatibility_routes.dart`：旧主页面、设置与图床参数入口转到新界面。

云端浏览与桶、目录、文件操作继续使用上游管理 API。云端文件列表、玻璃批量操作条、文件操作 Bottom Sheet、详情卡片、加载/空状态、重命名/新建目录表单与又拍云/Imgur 登录表单已重写。上传与下载管理接入新版主题；少量存储桶专用表单、预览与本地浏览页面仍沿用上游布局，尚未达到所有细分页视觉全部替换的目标。

## 数据与兼容

仓库不预设假配置。首次运行会读取备用配置 A–Z，并把尚未收录的上游活动配置迁入空位。每类活动配置只自动迁移一次，删除配置不会从旧文件复活。

默认图床按配置 ID 保存；临时上传目标只在当前会话生效。上传开始后固定配置快照，整个批次使用同一目标，并阻止上传期间切换、编辑或删除配置。上传失败不入库；部分成功保留成功记录，并可重试最后失败的文件。

数据库使用 Picora 的应用私有目录，不自动共用旧项目的 Downloads 数据库；旧配置通过显式导入迁移。数据库列保持上游格式，时间和配置归属保存在 `picora-album-meta.json`。旧记录没有全局时间戳，所以跨图床无法精确推断先后；旧记录会出现在相册，但上传页最近记录仅展示已知时间的记录。

相册支持按具体仓库配置或图床平台筛选；配置归属在新记录元数据中保留。旧记录缺少配置归属，只归入平台相册。默认只删除记录；云端/本地删除行为由设置控制，并在执行前显示实际删除范围。

GitHub 记录的复制地址采用 raw/custom domain URL，数据库仍保留删除所需的原始记录。图片链接上传仅接受 HTTP/HTTPS，校验图片响应与 50 MB 限制。

插件图床配置独立保存在应用支持目录，上传记录写入预留扩展表。运行时只执行经过校验的 HTTP 请求模板，并按清单限制目标主机、明文 HTTP、超时和重定向。“示例”插件基于现有 Telegraph-Image PicGo 插件移植；直接复用其他 PicGo 插件可通过 PicGo Bridge，原生扩展格式见 `docs/PLUGINS.md`。

## 诊断

日志位于应用支持目录 `picora-diagnostics.jsonl`，保留最近 300 条。每条含 ID、UTC 时间、操作、异常类型、上下文、堆栈；Dio 故障补充请求方法、脱敏 URL、状态码、错误类别与响应。原有 `flogErr` 已接入同一出口。

密钥、密码、Token、Authorization、Cookie、pictureKey 与签名 URL 参数自动脱敏。任意异常对象不直接转成字符串，避免第三方 SDK 把凭据拼进错误文本。导出的配置备份包含必要的图床密钥；诊断导出不包含这些密钥。

## 测试

数据层覆盖字段兼容、配置转换、链接校验、固定目标上传、部分成功重试、GitHub 复制、日志脱敏、删除后配置不复活、默认保留原图。

UI 覆盖四页面导航、空状态、目标/平台 Bottom Sheet、配置编辑、链接输入校验、三种相册视图、搜索、多选、320px 深色模式。预览由真实 Flutter Widget 渲染生成。同平台多配置相册独立筛选另有覆盖。云端组件测试覆盖批量下载、排序清空选择、320px 深色操作面板、删除确认、异步确认等待与取消、重命名校验与覆盖选项、登录校验。

## 设备验收

旧应用曾用工程内的 Android SDK 36、NDK 27.0.12077973、Gradle 8.10.2 与 Java 21 完成 Debug 构建。Picora 改名后尚未编译 APK；目标交付文件为 `releases/Picora-arm64-debug.apk`，Debug / Release 包名均为 `io.github.alnitak44.picora`，最低 Android 7.0（API 24）。新 APK 仍需重新核对应用名称、包名、签名与唯一 ARM64 架构，并在真机验收。真实上传需要使用者自己的图床凭据，自动测试没有触碰真实云端数据。

在 Android 真机验收：首次启动空仓库 → 添加任意平台配置 → 设默认 → 图片选择上传 → 验证三种复制格式 → 链接下载上传 → 拍照/连续拍照 → 从系统分享面板发送图片 → 相册三视图与筛选 → 多配置临时切换 → 重启确认默认配置 → 错误凭据/断网时检查日志 → 配置导出导入 → 云端浏览下载与目录操作。

iOS 沿用上游工程，其原 README 已说明未提供可用 iOS 版本；本轮没有宣称 iOS 打包或运行通过。
